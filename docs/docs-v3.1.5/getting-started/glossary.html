Glossary#

Terms used across these docs, in alphabetical order. Each entry links to the page that explains it in full.

Term

Meaning

See

Access request

A request from a user for access to an application they aren’t assigned to. An administrator approves or dismisses it.

Access Requests

Application custom resource

The declarative Kubernetes resource each installed application is modeled as. The platform reconciles it into a Helm release, so you never run Helm by hand.

Application Management

App Store

The page where users install applications, such as their Workspace.

Workspace

Browse Catalog

The admin console tab (under Applications) that lists the applications an administrator can install.

Application Management

Cluster ID

The identifier of your cluster. A license is bound to one cluster, so DKube needs it to issue a license.

Licensing

CRD

A Kubernetes custom resource definition. DKubeX uses the Application CRD for applications; ModelStudio deploys LLMs as KubeAI Model CRDs and ML models as KServe InferenceService CRDs.

Application Management, ModelStudio › Deploying models

Deployer

The component that serves an LLM deployed from ModelStudio, chosen in the deploy form: KubeAI (CPU or GPU, all engines) or NVIDIA Dynamo (vLLM).

ModelStudio › Deploying models

dkubex-installer

The Helm chart that installs DKubeX. Its values are listed in the Helm Values Reference.

Helm Values Reference

GGUF

A quantized model format. The Ollama engine runs GGUF models, so a model can be deployed without a GPU.

Deploying a Model on CPU

Guardrail

An automatic safety filter in SecureLLM that inspects AI requests and responses before they reach the AI or your users.

SecureLLM › Admin features

HAMi

The GPU sharing component (scheduler and device plugin) installed with DKubeX. It lets several models share one GPU through ModelStudio’s GPU Memory (GiB) setting.

Helm Values Reference, ModelStudio › Deploying models

KServe

The serving layer for classic machine-learning models (for example sklearn, XGBoost, PyTorch), deployed from an MLflow registry or HuggingFace.

Architecture & Specifications, ModelStudio

KubeAI

The serving layer for large language models and embedding models.

Architecture & Specifications, ModelStudio

License, seat

DKubeX applications are gated by seat-based licenses. A license is issued for one cluster and grants a number of seats per application: one seat per user, per application.

Licensing

Model cache

A ModelStudio setting that gives each deployer one shared cache disk, so a model is downloaded once and doesn’t re-download on scale-up or redeploy.

ModelStudio › Getting started

NGC API key

An NVIDIA NGC Personal API Key, added in ModelStudio Settings as your NVIDIA NIM token, needed to deploy NIM models.

ModelStudio › Deploying models

NIM

NVIDIA NIM models: registered from the NVIDIA NGC catalog and deployed in-cluster on GPU nodes.

ModelStudio › Deploying models

NVIDIA Dynamo

One of the two deployers for LLMs in ModelStudio, next to KubeAI; it serves models with vLLM.

ModelStudio › Deploying models

OAuth2 Proxy

The authentication layer you turn on under Config → Auth & Certs to sign users in through GitHub or OIDC, giving single sign-on across every application.

Configuration

Ollama

The inference engine for CPU deployments; it runs GGUF models.

Deploying a Model on CPU

PAT

A GitHub personal access token. The install command asks for one with access to the DKubeX repository (REGISTRY_TOKEN), and publishing an app to the App Store uses a classic personal access token.

Installation, Publishing an app

Placeholder

A value in angle brackets in a command, such as <admin_email> or <rwx_storage_class>. Replace it with your own value before you run the command.

Installation

pre_call / post_call

A guardrail’s mode in SecureLLM: a pre_call guardrail inspects the request before it reaches the model; a post_call guardrail inspects the model’s response.

SecureLLM › Admin features

Resource profile

A named resource configuration (CPU, memory, GPU) in ModelStudio that you load into the deploy forms: either your own custom profile or a read-only bundled KubeAI profile managed by the administrator. A GPU deployment requests its GPUs through the resource profile you select.

ModelStudio › Getting started, Deploying a Model on GPU

RWX (ReadWriteMany)

A storage access mode that lets user workspaces and apps share volumes across pods and nodes, which a ReadWriteOnce class cannot do. DKubeX needs RWX storage, from an external NFS server or a StorageClass that supports it.

Installation › Production recommendations

SecureLLM

Your organization’s secure gateway to AI: every AI request goes through one central hub your team controls, for consistent access, cost tracking and safety guardrails.

SecureLLM

Single sign-on (SSO)

Signing in once with your organization’s existing credentials to use every DKubeX application, with no separate account or password.

Quickstart, Architecture & Specifications

User policy

A per-user restriction in SecureLLM on which providers and models a user can call, with an optional spend limit. Set on the User Restrictions page, opened from the User Policies menu item.

SecureLLM › Admin features

vLLM

The inference engine for GPU deployments.

Deploying a Model on GPU

Workspace

Your personal, on-demand development environment in the cluster, installed from the App Store, with JupyterLab, VS Code, a terminal, a file browser and AI coding agents.

Workspace
